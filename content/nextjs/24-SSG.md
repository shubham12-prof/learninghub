# SSG

Static Site Generation — pages are rendered to HTML **once, at build time**, then served as static files from a CDN for every subsequent request — the fastest possible strategy, since no server work happens per-request.

```tsx
// app/blog/[slug]/page.tsx
export async function generateStaticParams() {
  const posts = await getAllPostSlugs();
  return posts.map((post) => ({ slug: post.slug })); // tells Next.js which pages to pre-render at build time
}

async function getPost(slug: string) {
  const res = await fetch(`https://api.example.com/posts/${slug}`); // default caching = static
  return res.json();
}

export default async function BlogPost({
  params,
}: {
  params: { slug: string };
}) {
  const post = await getPost(params.slug);
  return <article>{post.content}</article>; // this exact HTML is generated ONCE, at build time
}
```

**A route qualifies for full SSG when:**

- It has no dynamic data sources that force per-request rendering (no `cookies()`, `headers()`, `no-store` fetches, or dynamic `searchParams` usage)
- Any dynamic route segments (`[slug]`) have their possible values enumerated via `generateStaticParams`

**Fallback behavior for dynamic params NOT included in `generateStaticParams`:** by default, Next.js will still render (and then cache) those pages on-demand the first time they're requested — a hybrid behavior sometimes called "static + on-demand."

**SSG's core tradeoff:** blazing-fast, cheap to serve (just static files, works great behind a CDN), but content is frozen at build time — any change requires a rebuild (or ISR-style revalidation, see that file, to update without a full rebuild).

**When to choose pure SSG:** content that's the same for every visitor and doesn't change often — marketing pages, documentation, blog posts that rarely get edited after publishing.

**Interview note:** the App Router doesn't have a separate `getStaticProps` function like the old Pages Router — instead, a route is automatically statically generated by DEFAULT unless something in it (a `no-store` fetch, reading cookies, etc.) forces dynamic rendering — SSG is the implicit baseline, not something you opt into explicitly.
